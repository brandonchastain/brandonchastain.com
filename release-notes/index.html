2026-W43 (Oct 19 to Oct 25, 2026)

Week in a sentence: Feeds gained a hub, popular-feed suggestions and a longer admin trends range, the database now stores each post once, deploys restore from a continuously replicated copy of the database, and the release-notes bot stopped repeating itself.

brandonchastain/brandonchastain.com

Improvements

  • Weekly summaries are grouped by category in a fixed order, merge related changes into one outcome each, and report only what is new since the earlier weeks, so long-running work is no longer restated every Sunday.

Fixes

  • A week whose summary can't be generated now publishes as a plain list with a one-line note, and the model's output budget is raised so a large week no longer runs out before the summary is written.

brandonchastain/rss-reader

New features

  • The Feeds page is now a hub of cards, each with its own page. Subscribed feeds show their real titles, tags can be removed, and a Popular feeds list suggests the most-subscribed feeds. New accounts start with five starter feeds.
  • The admin dashboard's trends now span 1 hour to 1 year, with snapshots every few minutes while the app runs. The stat cards open drill-down tables where an admin can delete users, feeds or posts, and Refresh now takes a snapshot immediately. Snapshot retention rose from 30 to 400 days.

Improvements

  • Microsoft sign-in is now for personal accounts only; work and school accounts are sent back with a message. Sign-in asks only for email, and sessions last 30 days across browser restarts.
  • Each post is stored once per feed instead of copied for every subscriber, with existing data migrated in place. Unsaved posts older than 180 days are removed nightly, and feeds with no subscriber for 7 days are dropped.

Performance

  • On a 200-user scroll test against a copy of production data, the timeline went from 198 to 798 requests a second, and p95 page load fell from 2,569 ms to 3.7 ms.
  • Search answers from the full-text index: a rare word went from 109 to 216 ms down to 17 to 20 ms. Words that start mid-word, such as "flare" in "cloudflare", no longer match.
  • Scheduled feed refreshes are paced at 10 a second by default. In a 50-requests-a-second test, p95 fell from 513 ms to 30 ms with a 5-a-second budget, and a cycle of 5,000 due feeds stretched from about 80 s to 999 s.

Reliability

  • The database is replicated continuously to blob storage, and a new revision restores from that copy. A failed restore now restarts the container rather than starting empty. The first deploy on this path had about 117 s of 503s on /api/user; after the fixes, the probe saw no 5xx across 61 samples.

Fixes

  • Feeds that keep failing back off from 2 minutes to a 6-hour cap, and the backoff now survives restarts. Previously one dead feed was retried every scheduler tick and reached 45 failed fetches in a day. The Feeds page marks such feeds "not updating" and shows the reason.
  • Cross-site requests that change data are refused. The two actions reachable from a plain link are closed: marking a post read via GET is gone, and deleting a feed now uses DELETE.

2026-W42 (Oct 12 to Oct 18, 2026)

Week in a sentence: The site gained a weekly Release Notes page that now rebuilds on every deploy, while rss-reader moved sign-in into its API, hardened deploys and cost, and fixed a run of timeline and read-state bugs.

brandonchastain/brandonchastain.com

  • Added a weekly Release Notes page at /release-notes/ (renamed from /shipped/), linked from the home page. A Sunday-evening bot summarizes the week's commits, merged PRs and releases across my repos and commits the result to master so the site deploys. The first week (2026-W42) is seeded from a real run, and the fallback summary is kept short with the raw list in a collapsible block.
  • Every site deploy now regenerates the page from the committed week files, so it can't go stale. Week ids come from the window midpoint, so the Monday 02:00 UTC run files under the week it covers.
  • The bot skips repos its token can't read instead of crashing, and it rebases before pushing so overlapping runs no longer fail with "fetch first".

brandonchastain/rss-reader

  • Moved login off Static Web Apps Easy Auth and into the API, with Google, Microsoft and GitHub providers behind /auth/*. The cutover on 2026-10-17 made Microsoft login go through the API, and the Functions proxy is retired. Existing accounts are linked by a hash of the Microsoft-reported email, the admin checks work after the migration, and the account picker always appears.
  • Deploys no longer lose user writes. The new revision hands the database over from the old one before it starts, which closes a window of up to 15 minutes of lost writes on every deploy.
  • Kept one replica warm to fix a 45.6s cold start that ended in a 500, and cut idle-time work (backups, scheduler, probes) to bring the bill back down.
  • Timeline and read state fixes: the cached timeline reconciles with the server on every open, the list no longer jumps under the reader while paging, the "new posts" toast works on first load and stays off Search and per-feed pages, read posts stay visible until the next fetch, and a post stays read after Back from an outbound link. Manual refresh now fetches every stale feed.
  • Added self-hosting, architecture and knobs docs for the API, with 20 production deployments this week.
